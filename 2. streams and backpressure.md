# 🌊 Streams + Backpressure in Node.js

**Complete Concepts, Intuition, and Runnable Examples**

---

## 1️⃣ Why Streams Exist (The Big Picture)

### The Problem Without Streams

Imagine a server endpoint that serves a **large MP4 file**:

* Server reads the **entire file into memory**
* Sends it as a response
* If **5 users** hit the endpoint simultaneously →
  **Memory usage = 5 × file size**

This is a **classic Out-Of-Memory risk**.

### The Stream Solution

With streams:

* File is **read once**
* Data is sent **chunk by chunk**
* Memory usage stays **almost constant**, even with many users

📌 This is why **video streaming, file uploads, logs, ETL pipelines** all rely on streams .

---

## 2️⃣ Stream Intuition — Bucket & Hose Analogy

Think of:

* **Source bucket** → file / request / stdin
* **Destination bucket** → response / file / DB
* **Buffer bucket** → memory
* **Hose pipe** → stream

❌ Without streams:
Fill the buffer bucket fully → carry → empty → repeat

✅ With streams:
Connect source → destination using a hose → water flows **gradually**

This avoids memory overflow and enables **continuous processing** .

## 3️⃣ Core Stream Types (Mental Model)

| Stream        | Responsibility                    |
| ------------- | --------------------------------- |
| **Readable**  | Produces data in chunks           |
| **Writable**  | Consumes data in chunks           |
| **Duplex**    | Read + Write (middle of pipeline) |
| **Transform** | Read → modify → write             |

Common built-ins:

* HTTP request / response
* File system streams
* TCP sockets
* `process.stdin`, `process.stdout`
* gzip / unzip streams

## 4️⃣ Readable Streams (Deep Understanding)

### Events You Must Know

* `'data'` → chunk received
* `'end'` → no more data
* `'error'` → failure

### Data Modes

Readable streams can emit:

* **Binary** (default)
* **String** → `{ encoding: 'utf-8' }`
* **Objects** → `{ objectMode: true }` 

---

### Example: Readable.from + Custom Readable

```js
const { Readable } = require('stream');

// Flowing mode
Readable.from(['A\n', 'B\n', 'C\n'])
  .on('data', d => process.stdout.write(d))
  .on('end', () => console.log('Done'));

// Object mode
class ArrayReadable extends Readable {
  constructor(items) {
    super({ objectMode: true });
    this.items = items;
  }
  _read() {
    this.push(this.items.shift() || null);
  }
}

new ArrayReadable([{ id: 1 }, { id: 2 }])
  .on('data', d => console.log(d));
```

## 5️⃣ Flowing vs Non-Flowing Mode (Important Interview Topic)

### Flowing Mode

* Data is **pushed automatically**
* Triggered by `.on('data')`

### Non-Flowing (Paused) Mode

* Data is pulled **only when requested**
* Controlled using:

  * `readStream.pause()`
  * `readStream.read()`
  * `readStream.resume()` 

📌 This gives **fine-grained control** over data flow.

## 6️⃣ Writable Streams

### Core APIs

* `write(chunk)`
* `end()`

### Events

* `'finish'`
* `'close'`
* `'error'`

```js
const fs = require('fs');

const ws = fs.createWriteStream('out.txt', {
  highWaterMark: 16 * 1024
});

ws.write('Hello\n');
ws.end('Final line\n');

ws.on('finish', () => console.log('Finished'));
```

## 7️⃣ Backpressure (MOST IMPORTANT CONCEPT)

### Intuition (Funnel Analogy)

* Readable = pouring water
* Writable = narrow funnel
* Funnel fills up → **backpressure**
* Funnel capacity = **highWaterMark**

When writable is full:

* `write()` → returns **false**
* Readable must **pause**
* Resume only after `'drain'` event 

---

### Manual Backpressure Handling (Must-Know)

```js
const fs = require('fs');

const rs = fs.createReadStream('bigfile.dat', { highWaterMark: 64 * 1024 });
const ws = fs.createWriteStream('dest.dat', { highWaterMark: 16 * 1024 });

rs.on('data', chunk => {
  if (!ws.write(chunk)) {
    rs.pause();
  }
});

ws.on('drain', () => rs.resume());
rs.on('end', () => ws.end());
```

## 8️⃣ Pipes & Pipelines

### `pipe()`

* Automatically handles backpressure
* ❌ Manual error handling

### `pipeline()` (Production-Grade)

* Handles backpressure
* Cleans up streams
* Propagates errors

```js
const { pipeline } = require('stream');
const fs = require('fs');
const zlib = require('zlib');

pipeline(
  fs.createReadStream('input.txt'),
  zlib.createGzip(),
  fs.createWriteStream('out.gz'),
  err => {
    if (err) console.error(err);
    else console.log('Pipeline success');
  }
);
```

## 9️⃣ Duplex & Transform Streams

### Duplex

* Middle of pipeline
* Reads and writes
* Often used for **throttling, networking**

### Transform

* Special duplex
* Modifies data

```js
const { Transform } = require('stream');

class VowelMask extends Transform {
  _transform(chunk, _, cb) {
    cb(null, chunk.toString().replace(/[aeiou]/gi, 'X'));
  }
}

process.stdin
  .pipe(new VowelMask())
  .pipe(process.stdout);
```

## 🔟 Throttling (Slow Consumer Simulation)

```js
class Throttle extends Transform {
  constructor(ms) {
    super();
    this.ms = ms;
  }
  _transform(chunk, _, cb) {
    setTimeout(() => cb(null, chunk), this.ms);
  }
}
```

Used to:

* Simulate slow networks
* Control throughput
* Demonstrate backpressure propagation

## 1️⃣1️⃣ Streaming File Uploads (Busboy)

Why?

* Avoid buffering full files
* Scales for large uploads

```js
const Busboy = require('busboy');

busboy.on('file', (_, file, filename) => {
  file.pipe(fs.createWriteStream(`uploads/${filename}`));
});
```

## 1️⃣2️⃣ Video Streaming with Range Requests

Key idea:

* Client requests **partial bytes**
* Server responds with `206 Partial Content`
* Enables seeking

```js
fs.createReadStream('video.mp4', { start, end }).pipe(res);
```

This is how **YouTube / Netflix** work internally.

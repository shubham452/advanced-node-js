## 1️⃣ Starting With Node Internals (00:00:00)

### What Node.js really is (mental model)

Node.js is **not a language** and **not a framework**. It is:

> A **C/C++ runtime** that embeds the **V8 JavaScript engine** and exposes OS-level features to JavaScript.

### Core building blocks

```
┌───────────────┐
│ JavaScript    │  ← your code
└───────▲───────┘
        │
┌───────┴───────┐
│ V8 Engine     │  ← JS execution (Google Chrome)
└───────▲───────┘
        │
┌───────┴───────┐
│ Node APIs     │  ← fs, http, timers, etc.
└───────▲───────┘
        │
┌───────┴───────┐
│ libuv (C)     │  ← event loop, async I/O, thread pool
└───────▲───────┘
        │
┌───────┴───────┐
│ OS Kernel     │
└───────────────┘
```

Key takeaway:
👉 **JavaScript never talks to the OS directly.**

## 2️⃣ Module Implementations (00:03:47)

### How `require()` actually works

When you write:

```js
const fs = require('fs');
```

Node internally wraps every file like this:

```js
(function (exports, require, module, __filename, __dirname) {
  // your code here
});
```

### Module resolution flow

```
require('x')
   │
   ├─ Is it a core module? (fs, http)
   │
   ├─ Is it a file? (./x, ../x)
   │
   ├─ Is it in node_modules?
   │
   └─ Cache the result
```

### Important behavior: module caching

```js
// a.js
console.log("loaded");
module.exports = {};
```

```js
// b.js
require('./a');
require('./a');
```

Output:

```
loaded
```

Why?
👉 Modules execute **once**, then are cached in `require.cache`.

## 3️⃣ Node Backed by C / C++ (00:12:11)

### Why Node needs C++

JavaScript **cannot**:

* Access files
* Open sockets
* Spawn threads
* Do non-blocking I/O efficiently

So Node exposes **bindings** written in C++.

### Example: `fs.readFile`

```
JS call
  ↓
C++ binding
  ↓
libuv async I/O
  ↓
OS kernel
  ↓
callback queued
```

### Observable proof (experiment)

```js
const fs = require("fs");

console.log("start");

fs.readFile("file.txt", () => {
  console.log("file read");
});

console.log("end");
```

Output:

```
start
end
file read
```

JS didn’t block → C++ + libuv handled it.

## 4️⃣ The Basics of Threads (00:18:44)

### Common misconception

❌ Node.js is single-threaded
✅ **JavaScript is single-threaded**

Node internally uses **multiple threads**.

### Thread types

1. **Main thread** – executes JS
2. **Thread pool** (libuv)

   * fs
   * crypto
   * dns
   * compression

Default thread pool size: **4**

### Thread pool example

```js
const crypto = require("crypto");

for (let i = 0; i < 4; i++) {
  crypto.pbkdf2("pass", "salt", 100000, 64, "sha512", () => {
    console.log("done");
  });
}
```

Run once → fast
Run with 6 calls → noticeable delay
👉 Shows **thread pool saturation**

## 5️⃣ The Node Event Loop (00:25:14)

### What the event loop does

It decides **when callbacks execute**.

### Event loop phases (simplified)

```
┌──────── timers (setTimeout)
│
├──────── I/O callbacks
│
├──────── poll (waiting for I/O)
│
├──────── check (setImmediate)
│
└──────── close callbacks
```

![Image](https://media.geeksforgeeks.org/wp-content/uploads/20200224050909/nodejs2.png)

![Image](https://docs.libuv.org/en/v1.x/_images/architecture.png)

### Microtasks vs Macrotasks

* **Microtasks**: `process.nextTick`, `Promise.then`
* **Macrotasks**: `setTimeout`, `setImmediate`

### Ordering example (very important)

```js
setTimeout(() => console.log("timeout"), 0);

setImmediate(() => console.log("immediate"));

process.nextTick(() => console.log("nextTick"));

Promise.resolve().then(() => console.log("promise"));
```

Output:

```
nextTick
promise
timeout / immediate (order may vary)
```

Rule:

```
nextTick > Promise > Event Loop phases
```
